데이터 S1 제출물에 실존 인물의 실명·전화번호·이메일 등 PII가 포함되지 않았다. (더미 데이터 사용)
예
근거: 테스트 및 목(mock) 응답 검증에 사용하는 데이터는 가상의 컨퍼런스콜 문장(예: "2026년 4분기 D램 출하량은 10% 증가할 것으로 예상합니다" 등)과 수치뿐이며, 실존 인물의 개인정보(PII)는 전혀 포함되지 않았음.

데이터 S2 외부 AI(챗봇·API)에 기업 기밀·타인 코드·PII를 입력하지 않았다.
예
근거: AI 챗봇에는 우리 팀이 직접 작성한 설계 문서 V1, 구현 가이드(Pseudocode 및 제약 조건), 가주제 설명 텍스트만 입력했으며, 외부 기업 기밀이나 타인의 코드, 실제 API 키, 개인정보는 일절 입력하지 않았음.

데이터 S3 외부 데이터 사용 시 출처·라이선스를 확인하고 PII 열을 비식별 처리했다.
예
근거: extract_guidance 및 내부 도우미 함수(_call_llm, _mock_guidance) 구현과 단위 테스트(T12~T16)에는 외부 실데이터를 직접 연동하지 않고, 테스트 명세표에 정의된 더미 텍스트와 규칙 기반 모의(mock) 응답만 사용함. (향후 활용될 컨퍼런스콜 텍스트 역시 공개된 실적발표 보도자료 전망 문단만 수기 정리하여 사용할 예정임.)

키 관리 S4 API 키·비밀번호가 소스코드에 하드코딩되어 있지 않다.
예
근거: llm_module.py의 _call_llm 함수는 기본값인 "mock" 모드에서 API 키 없이 동작하며, 추후 실제 모드에서도 os.getenv("ANTHROPIC_API_KEY")를 통해 환경변수에서만 키를 읽어오도록 작성하여 소스코드 내 하드코딩된 키나 비밀번호가 전혀 없음.

키 관리 S5 .env 파일이 .gitignore에 등록되어 있고, git ls-files 확인 결과 추적되지 않는다.
예
근거: 팀 공통 제약 조건에 따라 프로젝트의 .gitignore에 .env가 등록되어 있으며, 본 작업 내역(llm_module.py)의 git 상태 및 추적 파일 확인 결과 .env나 키 관련 파일이 추적되지 않음을 확인했음.

키 관리 S6 커밋 히스토리에 키가 노출된 적이 없다 (노출 시 폐기·재발급 완료를 명기).
예
근거: 내 커밋(이다현 담당 llm_module.py 브랜치 작업 내역)에는 API 키나 비밀값을 직접 기록한 파일이 없으며, 환경변수 호출 코드만 포함되어 있으므로 커밋 히스토리에 키가 노출된 이력이 없음.

키 관리 S7 키·비밀 값을 print/log/스크린샷으로 전체 출력하지 않았다.
예
근거: 팀 공통 코딩 규약에 따라 extract_guidance와 _call_llm 등 모든 함수 본문에 print 문이나 로그 출력 코드를 일절 사용하지 않았으며, API 키가 없거나 호출 실패 시에도 예외나 키 정보를 출력하지 않고 빈 문자열("")만 반환하도록 처리함.

AI 사용 S8 AI 사용 내역(프롬프트·채택·수정)을 과제 규정에 따라 기록·첨부했다.
예
근거: 구현 가이드에서 담당자 재량으로 남겨둔 사항(상수 구성, 마크다운 코드펜스 제거, 정규식 소수점·부호 허용 등)을 AI와 먼저 질의응답으로 확정한 과정, 불리언(True/False)·NaN 방어 및 JSON dict 타입 검증 등 비판적 숙고를 거쳐 수정·채택한 내역, 단일 파일(llm_module.py) 통합 구조를 확인한 과정을 모두 기록했음.

AI 사용 S9 (LLM 기능 포함 시) 사용자 입력 검증과 출력 검증(형식 확인)을 적용했다.
예
근거: LLM 기능 모듈(extract_guidance)로서 철저한 입출력 검증을 적용함. (1) 입력 검증: transcript_text가 None이거나 공백뿐이면 _call_llm을 호출하지 않고 즉시 status="empty_input"을 반환함. (2) 출력 검증: 응답 앞뒤의 마크다운 코드 블록을 제거한 뒤 JSON 객체(dict) 여부를 확인(실패 시 status="parse_error")하고, 6개 지정 키만 추출하며, price_outlook 허용값 검사(이외는 "NA"), 출하량 증가율 숫자 타입(bool·NaN 제외) 및 범위(-50.0~100.0) 검사, target_quarter 정규식("YYYYQn") 완전 일치 검사, hbm_comment 100자 제한 및 evidence 문자열 리스트 최대 3개 제한을 모두 적용함.

AI 사용 S10 (LLM 기능 포함 시) 시스템 프롬프트에 비밀 정보를 포함하지 않았다.
예
근거: GUIDANCE_PROMPT_TEMPLATE 상수에 작성된 지시문에는 추출할 6개 키의 스키마와 허용값 규칙, 순수 JSON 출력 지시만 포함되어 있으며, API 키나 내부 보안 정보 등 비밀 정보는 전혀 포함하지 않았음.
