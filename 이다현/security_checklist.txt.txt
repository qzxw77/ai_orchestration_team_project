데이터 S1 제출물에 실존 인물의 실명·전화번호·이메일 등 PII가 포함되지 않았다. (더미 데이터 사용)
예
근거: 테스트 데이터는 직접 만든 가상의 증감률 숫자와 방향(상승/하락) 텍스트 값뿐이며, 실존 인물의 개인정보는 전혀 없음.

데이터 S2 외부 AI(챗봇·API)에 기업 기밀·타인 코드·PII를 입력하지 않았다.
예
근거: AI 챗봇에는 팀에서 작성한 설계 문서(함수 명세 프롬프트)와 더미 테스트 코드만 입력했으며, 실제 데이터나 키, 개인정보는 넣지 않았음.

데이터 S3 외부 데이터 사용 시 출처·라이선스를 확인하고 PII 열을 비식별 처리했다.
예
근거: compare_guidance 구현과 테스트에는 외부 API나 실데이터를 직접 호출하지 않고, 내부에서 생성한 더미 딕셔너리(모의 데이터)만 사용함.

키 관리 S4 API 키·비밀번호가 소스코드에 하드코딩되어 있지 않다.
예
근거: compare_guidance는 숫자와 문자열의 조건 비교 연산만 수행하므로 API 키나 외부 호출이 필요 없으며, 소스코드에 키가 하드코딩되지 않았음.

키 관리 S5 .env 파일이 .gitignore에 등록되어 있고, git ls-files 확인 결과 추적되지 않는다.
예
근거: 프로젝트 전체 설정으로 .gitignore에 .env가 등록되어 있으며, 본 작업 내역(forecaster.py)의 git 상태 확인 결과 키 관련 파일이 추적되지 않음을 확인했음.

키 관리 S6 커밋 히스토리에 키가 노출된 적이 없다 (노출 시 폐기·재발급 완료를 명기).
예
근거: 내 커밋(이다현 이름으로 된 브랜치 작업 내역)에는 API 키나 비밀값을 다루는 파일이 없으므로 노출된 이력이 없음.

키 관리 S7 키·비밀 값을 print/log/스크린샷으로 전체 출력하지 않았다.
예
근거: compare_guidance 함수 본문과 테스트 코드에는 print 문이나 로그 출력이 전혀 없으며 키를 다루지 않음.

AI 사용 S8 AI 사용 내역(프롬프트·채택·수정)을 과제 규정에 따라 기록·첨부했다.
예
근거: 초기 설계안의 한계(예외 처리 부족 등)에 대해 챗봇과 나눈 피드백 과정, 방어 로직이 추가된 코드 채택 및 pytest 통과 과정 등을 문서화하여 기록했음.

AI 사용 S9 (LLM 기능 포함 시) 사용자 입력 검증과 출력 검증(형식 확인)을 적용했다.
예
근거: compare_guidance 함수는 다른 함수가 생성한 결과를 받아 비교하는 로직만 수행하며, LLM API를 직접 호출하지 않아 해당 사항 없음.

AI 사용 S10 (LLM 기능 포함 시) 시스템 프롬프트에 비밀 정보를 포함하지 않았다.
예
근거: compare_guidance 함수는 LLM 기능을 직접 호출하여 사용하지 않으므로 해당 사항 없음.
