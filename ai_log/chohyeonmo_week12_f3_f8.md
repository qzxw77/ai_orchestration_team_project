## AI를 활용한 수정과 검토

예시 CSV를 다시 올리면 기존 자료를 갱신해도 화면에는 ‘새로 늘어난 행 0행’만 표시됐다(F3). 어떤 자료를 올려야 행이 추가되는지도 화면에서 알기 어려웠다(F8).

1. 백엔드의 `import_exports()`에서 정제한 자료와 저장된 자료의 월·지역·품목 코드 조합을 비교했다. 기존 조합을 교체한 수는 `updated`, 저장 표에서 늘어난 행 수는 `added`로 반환한다. 같은 값으로 다시 올린 행도 기존 키를 교체했으면 갱신으로 센다. [백엔드와 테스트 변경](https://github.com/qzxw77/ai_orchestration_team_project/commit/70dd052)
2. 화면의 `render_exports()`에서 두 수치를 ‘새로 추가된 행’과 ‘기존 행 갱신’으로 표시하고, 지표 바로 아래에 새 달의 자료를 추가하는 예시를 넣었다. 건수 계산은 백엔드가 맡고 화면은 반환값을 표시하도록 검토했다. [화면 변경](https://github.com/qzxw77/ai_orchestration_team_project/commit/8575a29)
3. 기존 자료를 다시 올리는 경우와 새 자료가 일부 섞인 경우를 나눠 확인했다. 혼합 입력에서는 표시 건수와 함께 저장된 수출액도 검사했다. 반환값에 추가된 `updated`의 의미를 모듈 문서에도 기록했다. [반환값 문서 변경](https://github.com/qzxw77/ai_orchestration_team_project/commit/599980d)

## 검증 결과

테스트는 임시 데이터 폴더에서 실행했다.

| 입력 | 새로 추가된 행 | 기존 행 갱신 | 함께 확인한 결과 |
|---|---:|---:|---|
| 빈 저장소에 예시 CSV를 처음 업로드 | 68 | 0 | 정제된 자료 68행이 저장됨 |
| 같은 CSV를 다시 업로드 | 0 | 68 | 저장 표가 68행으로 유지됨 |
| 기존 키 1행과 새 키 1행을 함께 업로드 | 1 | 1 | 기존 키의 수출액이 100에서 300으로 교체됨 |
| 열 이름만 있는 CSV를 업로드 | 0 | 0 | 정제된 행도 0행 |

저장소 최상위에서 `python -B -m pytest -q -p no:cacheprovider alt_backend_week11/tests`를 실행한 결과 업로드 백엔드 테스트 **10개가 모두 통과**했다.
